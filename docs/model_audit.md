# IntelliReq Software Requirement Ambiguity Detection System
## System Architecture and Pre-Correction Audit Report

### 1. Pre-Correction Architecture Summary
The original project architecture operated on a largely deterministic, rule-based approach disguised as a machine learning system:
1. `dataset/software_requirements.csv` was ingested.
2. A `RuleBasedDetector` parsed the requirement using a small set of hardcoded keywords (e.g. "may", "might", "could", "easy").
3. A target label was automatically generated based entirely on whether a keyword was present.
4. Traditional TF-IDF text features, basic sentiment scores, and uncalibrated structural features were extracted.
5. A Random Forest classifier was trained on these features to predict the generated label.

### 2. Identified Limitations and Flaws
- **Data Leakage & Tautology:** Because the ground-truth labels for the original dataset were generated by the rule-based keyword detector, the Random Forest model was merely learning to replicate the hardcoded keyword dictionary rather than learning true semantic ambiguity. 
- **100% Accuracy Illusion:** The old model often achieved near 100% accuracy precisely because the dataset mapping was perfectly deterministic. The test set was structurally identical to the training set.
- **Inadequate Specificity/Testability Parsing:** The old model would blindly flag requirements as Ambiguous if a vague keyword appeared (e.g., "efficiently"), even if the sentence contained an explicit, measurable constraint (e.g., "The system shall process 500 requests efficiently within 2 seconds.").
- **Lack of True Semantic Understanding:** TF-IDF represents text as a sparse bag-of-words. It is unable to grasp the context of a requirement or the ordering of operations (e.g., "complete X before Y").

### 3. Corrections Made
The new implementation successfully addresses all identified flaws:
1. **New V2 Dataset**: A new 634-row dataset containing human-verified pseudo-labels and controlled semantic pairs, effectively untangling the tautological loop of the keyword detector.
2. **SBERT Semantics**: The system now utilizes a 384-dimensional dense semantic embedding from `sentence-transformers/all-MiniLM-L6-v2`.
3. **Specificity Guard**: We introduced measurable constraint extraction (tracking explicit bounds, thresholds, exact formats, percentages).
4. **Hybrid Modeling**: An L1-regularized Calibrated Logistic Regression model now properly balances semantic vectors against deterministic specificity overrides.
